# 8.1 ARP：由 IP 问出 MAC

## 为什么需要 ARP
- 发帧要知道对方的 **MAC 地址**
- 电脑只知道对方的 IP
- ARP：**广播**问“谁是 192.168.1.1？”
- 对方**单播**回答自己的 MAC
- 结果存进 **ARP 缓存**（`arp -a`）

::: notes
比喻：在办公室里喊一嗓子“谁是陈姐？”，陈姐走过来答一声。抓包 dhcp_arp.pcap 和 web_visit.pcap 的第 1、2 帧就是一问一答。
:::

## ARP 只在同一网段内用（考点）
- 路由器**不转发**广播
- 去别的网段：问的是**网关**的 MAC
- 每过一个路由器，重新 ARP 下一段

## 动手：ARP 问路
!sim arp
- 看请求怎样广播、响应怎样单播
- 打开“ARP 欺骗”开关
  - 攻击者冒充网关，数据被劫持

::: notes
ARP 不验证响应的真实性，所以存在 ARP 欺骗。防范：交换机开启 ARP 防护、绑定网关的 MAC 地址。现象：整个网段突然上不了网，arp -a 中网关的 MAC 变了。
:::

# 8.2 ICMP：回执与报错

## 常见 ICMP 报文
| 类型 | 名称 | 例子 |
|---|---|---|
| 8 | 回送请求 | ping 发出 |
| 0 | 回送回答 | ping 收到 Reply |
| 3 | 终点不可达 | 找不到路 |
| **11** | **时间超过** | tracert 每一跳 |
| 5 | 重定向 | 较少见 |

## ping 与 tracert
- **ping**：回送请求 / 回送回答
  - ping 不通不一定断：对方可能不回应
- **tracert**：TTL 从 1 开始递增
  - 每跳回“时间超过”
- ICMP 装在 **IP** 数据报里

# 8.3 DHCP：自动分配地址

## DHCP 四个步骤（考点）
| 步骤 | 报文 | 方向 |
|---|---|---|
| ① | **发现** Discover | 客户机 → 广播 |
| ② | **提供** Offer | 服务器 → 客户机 |
| ③ | **请求** Request | 客户机 → 广播 |
| ④ | **确认** ACK | 服务器 → 客户机 |

::: notes
比喻：新员工进门问“谁管发工位？”，行政说“给你 23 号”，新员工当众说“我要行政给的 23 号”，行政确认。发现报文源地址 0.0.0.0，目的 255.255.255.255。第 ③ 步还是广播，是为了告诉其他 DHCP 服务器“我选了别人”。
:::

## 动手：DHCP 四步
!sim dhcp
- 看每一步谁发给谁、用不用广播
- 分到地址、网关、DNS

## 租期、续租与 169.254
- 地址有**租期**，过半时续租
- 联系不上 DHCP 服务器 → **169.254.x.x**
- `ipconfig /release`、`/renew`
- 跨网段要 **DHCP 中继**（了解）

## 在路由器上配置 DHCP
```text
R1(config)#ip dhcp pool DESIGN
R1(dhcp-config)#network 192.168.8.0 255.255.255.192
R1(dhcp-config)#default-router 192.168.8.1
R1(dhcp-config)#dns-server 203.0.113.10
```

::: notes
实验 8-2。最好用 ip dhcp excluded-address 把网关等手工使用的地址排除，避免地址冲突。查看：show ip dhcp pool。
:::

# 8.4 NAT：私有地址怎样上互联网

## PAT：一个公网地址大家用（考点）
| 内部 | 转换后 | 外部 |
|---|---|---|
| 192.168.8.11:51001 | 198.51.100.2:51001 | 203.0.113.10:80 |
| 192.168.8.12:51001 | 198.51.100.2:**51002** | 203.0.113.10:80 |
| 192.168.8.71:50523 | 198.51.100.2:50523 | 114.114.114.114:53 |

::: notes
PAT 靠端口号区分不同主机的连接：两台电脑都用 51001，路由器把第二台改成 51002。比喻：公司总机，对外一个号码，分机号区分每个人。
:::

## 动手：NAT 转换表
!sim nat-table
- 内网电脑发起访问，表里添一行
- 回来的数据按表换回内部地址
- 外网主动来访：表里没有，进不来

## 配置 PAT
```text
R1(config)#access-list 1 permit 192.168.8.0 0.0.0.63
R1(config)#ip nat inside source list 1 interface gig0/1 overload
R1(config-if)#ip nat inside       ← 内部接口
R1(config-if)#ip nat outside      ← 外部接口
```

## NAT 的好处与麻烦
| 好处 | 麻烦 |
|---|---|
| 节省公网地址 | 外网不能主动访问内网 |
| 隐藏内部结构 | 违背端到端原则 |
| 内部地址随意规划 | 有性能开销 |

::: notes
NAT 不是防火墙：它的“隐藏”只是副作用，真正的访问控制要靠防火墙和 ACL（第 11 章）。家里搭网站外网访问不到，要在路由器上做端口映射。
:::

# 8.6 常见问题与 AI 与网络

## 本章常见问题对照
| 现象 | 原因 |
|---|---|
| 169.254.x.x | 联系不上 DHCP |
| IP 地址冲突 | 手工地址和 DHCP 撞了 |
| 网关 MAC 突然变了 | 可能 ARP 欺骗 |
| 家里网站外网访问不了 | NAT 挡住，需端口映射 |

## AI 与网络：手机为什么拿不到公网地址
- 4G/5G 地址常是 10.x 或 100.64～100.127
- 运营商又做了一层 NAT
- AI 摄像头、车联网要设备**直接通信**
- 出路：**IPv6**，每台设备都有公网地址
