# 2.1 协议：网络里的“约定”

## 协议的三要素
| 要素 | 规定什么 | 打电话的比喻 |
|---|---|---|
| **语法** | 格式和结构 | 先报姓名再说事 |
| **语义** | 每部分的意思和动作 | “喂”表示我在听 |
| **同步** | 先后顺序和时机 | 对方说完我再说 |

::: notes
网络中的例子：语法——以太网帧前 6 字节是目的 MAC；语义——TCP 首部 SYN=1 表示请求建立连接；同步——先握手、再传数据、最后断开。协议由 IETF（RFC）、IEEE 等组织制定。
:::

# 2.2 为什么要分层

## 寄一封信的过程
!mermaid 1
- 每层只管自己的事
- 上层依靠下层的**服务**
- 同层之间有**约定**
- 一层变了，其他层不受影响

## 分层的好处
- 各层**相对独立**
- **灵活**：网线换 WiFi，上层不用改
- 易于实现和维护：大问题拆小
- 便于**标准化**
- 层次 + 各层协议 = **体系结构**

# 2.3 OSI 七层模型

## 七层各做什么
| 层 | 名称 | 作用 |
|---|---|---|
| 7 | 应用层 | 为应用程序提供服务 |
| 6 | 表示层 | 格式转换、加密、压缩 |
| 5 | 会话层 | 建立、管理会话 |
| 4 | 传输层 | 端到端可靠传输 |
| 3 | 网络层 | 编址、选路 |
| 2 | 数据链路层 | 相邻节点间传帧 |
| 1 | 物理层 | 比特变信号 |

::: notes
口诀从下往上：物、数、网、传、会、表、应。OSI 没有流行：标准太慢、会话层和表示层功能太少、实现复杂。但它是讲解网络的通用参考。
:::

# 2.4 TCP/IP 模型与五层模型

## TCP/IP 四层模型
!mermaid 2
- 应用层：HTTP、DNS、SMTP、DHCP
- 运输层：**TCP、UDP**
- 网际层：**IP**、ICMP、ARP
- 网络接口层：以太网、WiFi

::: notes
互联网实际使用的是 TCP/IP 体系结构，不是 OSI。TCP/IP 的网络接口层本身没有具体规定。
:::

## 本书的五层模型（考点）
| 五层 | PDU | 典型设备 |
|---|---|---|
| 应用层 | 报文 | — |
| 运输层 | 报文段 / 用户数据报 | — |
| 网络层 | 分组（IP 数据报） | 路由器、三层交换机 |
| 数据链路层 | 帧 | 交换机、网卡 |
| 物理层 | 比特 | 集线器、中继器 |

::: notes
五层 = TCP/IP 的上三层 + 把网络接口层拆成数据链路层和物理层，兼顾教学和实际。设备所在层是高频考点：集线器只转发比特，在物理层；“三层交换机”的三层指 OSI 第三层网络层。
:::

## 每一层在问什么
| 层 | 要解决的问题 |
|---|---|
| 应用层 | 我要什么服务？ |
| 运输层 | 交给哪个程序？不丢不乱？ |
| 网络层 | 对方在哪？走哪条路？ |
| 数据链路层 | 下一站是谁？ |
| 物理层 | 0 和 1 怎么变信号？ |

# 2.5 封装与解封装

## 层层“装信封”
!mermaid 3
- 每层加上自己的**首部**
- 链路层还加**尾部**（校验码）
- 接收方逐层拆开：**解封装**

## 算一算：一个网页请求包了几层
| 层 | 部分 | 字节 |
|---|---|---|
| 数据链路层 | 以太网首部 | 14 |
| 网络层 | IP 首部 | 20 |
| 运输层 | TCP 首部 | 32 |
| 应用层 | HTTP 请求 | 154 |
| 合计 | | **220** |

::: notes
数据来自 web_visit.pcap 第 10 帧（实验 2-1 会打开）。真正的用户数据只有 154 字节，首部占了 66 字节。
:::

## 中间设备拆到哪一层
!mermaid 4
- **交换机**拆到链路层：看 MAC
- **路由器**拆到网络层：看 IP，**换新的帧首部**
- 只有两端主机拆到应用层

## 动手：封装与解封装
!sim encapsulation
- 一步步看首部怎样加上、拆下
- 注意经过路由器时帧首部换了

## 服务、接口与协议
!mermaid 5
- **服务**：下层为上层，**垂直**
- **协议**：对等层之间，**水平**
- **接口**：相邻层交换信息的地方

# 2.7 用 Wireshark 看见分层

## Wireshark 的界面
| 区域 | 显示什么 |
|---|---|
| 分组列表（上） | 每行一帧 |
| 分组详情（中） | 逐层解析，点开看首部 |
| 字节数据（下） | 原始十六进制 |

::: notes
强调法律边界：只能在自己的设备、自己管理或经授权的网络抓包。本书提供编者录制的抓包文件，课上直接打开 web_visit.pcap 演示。
:::

## 常用显示过滤器
| 过滤器 | 只显示 |
|---|---|
| `dns` | DNS 查询和回答 |
| `http` | HTTP 请求和响应 |
| `tcp` | TCP 报文段 |
| `arp` | ARP |
| `ip.addr == 203.0.113.10` | 与该地址有关的 |

::: notes
过滤栏变红说明写法不对：等于用两个等号，协议名小写。自己抓的包大多是 HTTPS，显示为 TLS，看 HTTP 明文用书里的抓包文件。
:::

# 2.8 常见问题与 AI 与网络

## 本章常见问题对照
| 现象 | 原因 |
|---|---|
| 分不清七层、四层、五层 | 三种模型，划分不同 |
| 搞混报文、分组、帧 | 不同层的 PDU |
| Wireshark 没网卡可选 | Npcap 没装好 |
| 自己抓包看不到 HTTP | 网站多用 HTTPS |

## AI 与网络：一次大模型调用穿过五层
- 应用层：HTTP 请求，JSON 格式的问题
- 运输层：TCP 连到 **443** 端口
- 网络层：IP 地址，一路路由器转发
- 链路层、物理层：WiFi、网线、光纤
