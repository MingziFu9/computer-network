# 9.1 运输层做什么

## 从主机到进程
| 层次 | 送到 | 标识 | 比喻 |
|---|---|---|---|
| 网络层 | 哪台主机 | IP 地址 | 公司地址 |
| **运输层** | 哪个进程 | **端口号** | 分机号 |

::: notes
运输层只在主机上，路由器转发时不看端口号（判断题第 12 题）。端口 16 位：熟知 0～1023，登记 1024～49151，临时 49152～65535。IP 地址 + 端口号 = 套接字，两端的套接字唯一确定一条 TCP 连接。
:::

## 常用端口号（考点）
| 应用 | 端口 | 应用 | 端口 |
|---|---|---|---|
| FTP | 21、20 | DNS | 53 |
| SSH | 22 | DHCP | 67、68 |
| Telnet | 23 | HTTP | 80 |
| SMTP | 25 | POP3 | 110 |
| IMAP | 143 | HTTPS | 443 |

# 9.2 UDP 与 TCP

## UDP：简单、快、不保证送到
- **无连接**，拿来就发
- 首部只有 **8 字节**
- 不确认、不重传、不排序
- 面向报文，一次一个完整报文
- 适合：视频会议、直播、DNS、DHCP

## UDP vs TCP
| | UDP | TCP |
|---|---|---|
| 连接 | 无连接 | 面向连接 |
| 可靠性 | 不可靠 | 可靠 |
| 数据单位 | 用户数据报 | 报文段（字节流） |
| 首部 | 8 字节 | 20～60 字节 |

## TCP 首部关键字段
| 字段 | 作用 |
|---|---|
| 源、目的端口 | 哪个进程 |
| **序号** | 本段数据第一个字节的编号 |
| **确认号** | 期望收到的下一个字节编号 |
| 标志位 | SYN、ACK、FIN、RST |
| **窗口** | 我还能收多少（流量控制） |

# 9.4 三次握手与四次挥手（考点）

## 三次握手
| 步 | 方向 | 标志 | 序号、确认号 |
|---|---|---|---|
| ① | 客户端 → 服务器 | **SYN** | seq = x |
| ② | 服务器 → 客户端 | **SYN + ACK** | seq = y，ack = x + 1 |
| ③ | 客户端 → 服务器 | **ACK** | seq = x + 1，ack = y + 1 |

::: notes
比喻打电话：喂听得到吗？听得到，你听得到我吗？听得到，开始说吧。为什么不是两次：服务器要确认客户端收到了自己的回复，还要防止迟到的旧连接请求让服务器白建连接。
:::

## 在抓包里看三次握手
```text
帧  方向           标志      序号（真实）     确认号（真实）
1   43108 → 9000   SYN       1314535487      —
2   9000 → 43108   SYN,ACK   1250116542      1314535488
3   43108 → 9000   ACK       1314535488      1250116543
```

::: notes
来自 tcp_udp_chat.pcap。Wireshark 默认显示相对序号（从 0 开始）。SYN 不带数据，也要消耗一个序号，所以确认号是对方序号加 1。
:::

## 序号和确认号怎么变
- A 发：seq = 200，带 100 字节
- B 回：ack = **300**
- 确认号 = 序号 + 数据长度
- 意思是“299 之前我都收到了”

## 四次挥手
| 步 | 方向 | 标志 | 意思 |
|---|---|---|---|
| ① | A → B | FIN | 我发完了 |
| ② | B → A | ACK | 知道了，我还要说 |
| ③ | B → A | FIN | 我也发完了 |
| ④ | A → B | ACK | 再见 |

::: notes
为什么四次：TCP 是全双工的，两个方向要分别关闭；B 收到 FIN 后可能还有数据没发完，所以 ACK 和 FIN 分两次发。
:::

# 9.5 可靠传输与流量控制

## 可靠传输三件宝
- **序号**：知道缺了哪段、按顺序拼
- **确认**：收到就回执
- **超时重传**：没回执就重发
- 比喻：寄挂号信

## 滑动窗口与流量控制
- 不必发一个等一个，一次发**一窗口**
- 收到确认，窗口向前**滑动**
- 接收方在**窗口**字段告诉“我还能收多少”
- **流量控制**：别发得比对方收得快

# 9.6 拥塞控制

## 四种算法（考点）
| 算法 | 窗口怎么变 |
|---|---|
| **慢开始** | 从 1 开始，每轮**翻倍** |
| **拥塞避免** | 到门限后每轮 **+1** |
| **快重传** | 3 个重复确认，立即重传 |
| **快恢复** | 门限减半，窗口 = 新门限 |

::: notes
流量控制看接收方，拥塞控制看网络。超时：门限减为当前窗口的一半，窗口回到 1 重新慢开始。3 个重复确认：快重传 + 快恢复，窗口直接设为新门限再拥塞避免。
:::

## 算一算：拥塞窗口怎么变
- 门限 16，第 9 轮后超时
  - 1、2、4、8、**16**、17、18、19、**20**
- 超时：门限 = 10，窗口回 1
  - 1、2、4、8、**10**、11、**12**
- 3 个重复确认：门限 = 6，窗口 = 6
  - 6、7、8……

# 9.7 TCP 与 UDP 怎么选

## 选择的原则
| 需求 | 选择 |
|---|---|
| 一个字节都不能错 | TCP：网页、下载、支付 |
| 实时比完整重要 | UDP：视频会议、游戏 |
| 一问一答、很小 | UDP：DNS、DHCP |
| 广播、多播 | UDP |

::: notes
QUIC（了解）：在 UDP 之上实现可靠传输和加密，HTTP/3 用它，握手更快。判断题：QUIC 运行在 UDP 上，不是 TCP。
:::

- 生成一点，就通过已建立的连接**发一点**
- 用 **TCP**：文字不能丢、不能乱
- 实时语音对话则更看重时延
