# 10.1 应用层与两种工作模式

## 常用应用层协议
| 应用 | 协议 | 运输层 | 端口 |
|---|---|---|---|
| 域名解析 | DNS | UDP | 53 |
| 网页 | HTTP / HTTPS | TCP | 80 / 443 |
| 发邮件 | SMTP | TCP | 25 |
| 收邮件 | POP3 / IMAP | TCP | 110 / 143 |
| 文件传输 | FTP | TCP | 21、20 |

## 客户—服务器与 P2P
| | 客户—服务器 | P2P |
|---|---|---|
| 服务器 | 需要，一直运行 | 不需要专门的 |
| 用户越多 | 服务器压力越大 | 可用上传能力越大 |
| 管理 | 集中 | 分散 |
| 例子 | 网站、邮件、网盘 | 文件分享、软件更新加速 |

# 10.2 域名系统 DNS（考点）

## 域名的层次结构
!mermaid 1
- 从右往左：根 → 顶级 → 二级 → 主机
- `www.xiaohe.com`：顶级域名 **com**
- DNS：把域名翻译成 IP 地址

## 四类域名服务器
| 类型 | 负责 |
|---|---|
| 根 | 知道所有顶级域名服务器 |
| 顶级 | 管一个顶级域名 |
| **权威** | 给出最终答案 |
| **本地** | 替用户查，并缓存 |

## 递归查询与迭代查询
- 主机 → 本地服务器：**递归**
  - 必须给出最终答案
- 本地 → 根、顶级、权威：**迭代**
  - 只告诉“下一步去问谁”
- 根服务器只指路，不跑腿

::: notes
比喻：打听一家店，递归是让秘书全权去办，迭代是每个人告诉你下一步问谁。根服务器不做递归，因为全世界的查询都经过它，负担太重。
:::

## 缓存与 hosts 文件
- 各级都有**缓存**，有过期时间
- 查询前先看 **hosts** 文件，优先于 DNS
- DNS 劫持：通讯录被人改了
- `nslookup`、`ipconfig /flushdns`

# 10.3 万维网与 HTTP

## URL：网页的地址
- `https://www.xiaohe.com:443/news/list.html?page=2`
- 协议 + 主机 + 端口 + 路径 + 查询参数
- 端口省略：http 80，https 443
- `#top` 是页面内的位置，不发给服务器

## HTTP 请求与响应
| 部分 | 请求 | 响应 |
|---|---|---|
| 第一行 | 方法 路径 版本 | 版本 状态码 原因 |
| 首部 | Host、User-Agent、Cookie | Content-Type、Content-Length |
| 空行 | 首部结束 | 首部结束 |
| 正文 | POST 的数据 | 网页、JSON |

## GET 与 POST
| 方法 | 作用 |
|---|---|
| **GET** | 获取，参数在 URL `?` 后 |
| **POST** | 提交，数据在正文 |
| PUT / DELETE | 修改 / 删除 |

::: notes
POST 的数据不显示在地址栏，但在 HTTP 中仍是明文，抓包就能看到（第 11 章用 http_vs_https.pcap 演示）。
:::

## 状态码（考点）
| 类别 | 含义 | 常见 |
|---|---|---|
| 2xx | 成功 | **200 OK** |
| 3xx | 重定向 | 301、302、304 |
| 4xx | 客户端错误 | 403 禁止、**404** 找不到 |
| 5xx | 服务器错误 | **500**、502、503 |

## Cookie 与 HTTP 版本
- HTTP **无状态**，靠 Cookie 认出同一用户
- 1.0：一个请求一个连接
- 1.1：持久连接
- 2：多路复用；3：基于 QUIC（UDP）

# 10.4 输入网址之后发生了什么

## 一次访问的 18 帧
| 步骤 | 帧 | 发生了什么 |
|---|---|---|
| 1 | — | 解析 URL |
| 2 | 1～2 | ARP 问网关 MAC |
| 3 | 3～6 | DNS 查到 203.0.113.10 |
| 4 | 7～9 | TCP 三次握手 |
| 5～6 | 10～15 | GET / → 200 OK |
| 7 | 16～18 | 四次挥手 |

::: notes
来自 web_visit.pcap：DNS 用 UDP 47003→53，TCP 35070→80，GET 请求 154 字节，响应 Content-Length 286，从 DNS 查询到收到网页约 6 毫秒。第 0 步开机时已用 DHCP 拿到地址、网关和 DNS。这是经典面试题，要求学生能按层说出来。
:::

# 10.6 邮件、文件传输与远程登录

## 电子邮件协议（考点）
| 协议 | 作用 | 端口 |
|---|---|---|
| **SMTP** | 发送 | 25（客户端 587 / 465） |
| **POP3** | 下载到本机 | 110 |
| **IMAP** | 在服务器上管理 | 143 |

## 文件传输与远程登录
| 方式 | 端口 | 特点 |
|---|---|---|
| FTP | 21、20 | 明文 |
| Telnet | 23 | 明文，不建议用 |
| **SSH** | 22 | 加密，管理设备标准方式 |
| 远程桌面 | 3389 | 图形界面 |

# 10.9 常见问题与 AI 与网络

## 本章常见问题对照
| 现象 | 原因 |
|---|---|
| 能 ping IP，域名打不开 | DNS 出问题 |
| 网页显示 404 | 路径不存在 |
| 500、502、503 | 服务器自己的问题 |
| 有人看到新网站有人看到旧的 | DNS 缓存未过期 |

## AI 与网络：大模型 API 的一次请求
```text
POST https://api.example.com/v1/chat HTTP/1.1
Host: api.example.com
Authorization: Bearer <你的 API 密钥>
Content-Type: application/json
```

::: notes
这是示意。方法 POST、HTTPS 加密、Authorization 首部带 API 密钥（相当于会员卡，绝不能泄露、不能写进公开代码），正文和响应都是 JSON。
:::
