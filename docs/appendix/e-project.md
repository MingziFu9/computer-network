# 附录 E 实验报告模板与综合项目指南

## E.1 实验报告模板

每个实验结束后提交一份实验报告。报告不求长，求真实：截图和数字都要来自你自己的运行结果。

```text
实验 N-M  实验名称
姓名：        学号：        日期：        运行环境：□ 云端 Notebook  □ 本机

一、实验目的（照抄实验开头的“实验目的”即可）

二、运行结果
  1. 第一档（跑通）：贴出关键输出和结果图截图
  2. 第二档（改一改）：每一项写“改了什么 → 结果怎么变 → 为什么”

三、实验记录表（按实验中的表格填写）

四、遇到的问题和解决办法（报错原文 + 怎么解决的；没有遇到可以不写）

五、思考与练习（回答实验最后的问题）

六、第三档挑战（选做）：做了什么、结果如何
```

**评分标准（每个实验 10 分）**

| 项目 | 分值 | 要点 |
|---|---|---|
| 第一档跑通 | 3 | 有运行结果截图，与书中结果基本一致（允许小数点后的差别） |
| 第二档改一改 | 3 | 每项都写清改了什么、结果怎么变；解释说得通 |
| 实验记录表 | 2 | 填写完整，数字来自自己的运行 |
| 思考与练习 | 2 | 回答切题，用自己的话 |
| 第三档挑战 | 加 1～2 分 | 选做，总分不超过 10 分 |

!!! tip "关于“和书上不一样”"
    模型版本、电脑性能不同，速度、置信度等数字会和书上略有差别，这是正常的，照实记录即可。差别很大（比如书上找到 8 个目标，你只找到 1 个）时，先检查图片路径、参数有没有改错。

## E.2 综合项目进度安排

综合项目即[实验 9-3](../chapters/09-applications/index.md#9-3)，建议在第 9 章开始前两周布置，2～3 人一组，也可以一个人做。

| 时间 | 任务 | 交付物 |
|---|---|---|
| 第 1 周 | 选题，写需求；跑通 `lab9_3_project_template.py` | 项目报告“一、需求” |
| 第 1～2 周 | 准备测试素材（至少 10 个，其中 3 个是难的情况）；把参考实验的代码搬进模板 | 网页能出第一个结果 |
| 第 2 周 | 测试、记录、调参；写合规自查表 | 项目报告“二～六” |
| 最后一次线下课 | 现场演示 5 分钟 + 提问 3 分钟 | 代码、报告、演示 |

## E.3 四个选题的实现提示

### 选题 A 智能辅助驾驶助手

- 起点：`labs/ch09/lab9_1_assistant_app.py`。
- 只对本车道提醒：在 `analyze` 里记下每个框的中心和底边，只有中心在画面中间 30%、底边在下方 40% 的目标才提醒（第 9 章课后练习第 20 题）。
- 视频输入：`inputs=gr.Video()`，函数收到的是视频文件路径；用 `cv2.VideoCapture` 逐帧读、调用分析、用 `cv2.VideoWriter` 写出，返回新视频的路径（实验 7-1）。视频先剪到 10 秒以内，或每 3 帧处理一次。
- 加分：叠加车道线检测（实验 3-3）；把检测模型换成第 5 章自己训练的 `best.pt`。
- 界面上必须写明“仅供学习演示，不能代替驾驶员”。

### 选题 B 安防计数

- 起点：`labs/ch07/lab7_2_track.py` 的越线计数和区域闯入部分。
- 网页输入视频，输出“通过人数”和画好号码牌、计数线的视频。
- 计数线位置可以用两个滑块（`gr.Slider`）调整。
- 注意：换一段视频要重新加载模型（`YOLO(...)`），否则号码牌会接着上一段编。
- 合规：只统计人数，不识别身份，不保存人脸截图。

### 选题 C 健身计数

- 起点：`labs/ch07/lab7_3_pushup_counter.py`。
- 换成深蹲：用髋—膝—踝（11-13-15 或 12-14-16 号关键点）的夹角，站立时接近 180°，蹲下时小于 100°左右；门槛要用自己录的视频测出来。
- 开合跳：用两手腕的距离和肩宽的比值。
- 用“连续几帧都满足才算”的规则防止抖动（第 7 章“动作是一段时间”动画）。
- 加分：判断“动作不标准”（如俯卧撑没压到位）并提示。

### 选题 D 证件照工具

- 起点：`labs/ch02/lab2_1_id_photo.py`（HSV 换底色）和 `labs/ch06/lab6_1_cutout.py`（分割抠图）。
- 一寸照尺寸：295×413 像素（宽×高）。先按人脸位置裁成 5:7 的比例，再 `cv2.resize`。
- 底色：红 (0, 0, 255)、蓝 (219, 142, 67)、白 (255, 255, 255)（BGR 顺序，可按需要微调）。
- 用分割模型抠图比按颜色换底色更通用，头发边缘可以用羽化（`cv2.GaussianBlur` 处理掩膜）让过渡自然。
- 合规：照片只在本机处理，不保存、不上传；不提供“换脸”“美颜改五官”等功能。

## E.4 项目报告模板

完整模板在 `labs/ch09/项目报告模板.md`，结构如下：

| 部分 | 内容 |
|---|---|
| 封面信息 | 项目名称、选题、成员与分工、日期 |
| 一、需求 | 谁用、在什么场合用；输入输出；“做得好”的标准 |
| 二、数据 | 来源、数量、是否含个人信息及处理方法、许可 |
| 三、方法 | 用了哪些模型和规则、参数取值和理由、流程图 |
| 四、结果与评估 | 测试表（正确结果 / 程序结果 / 对错 / 错因）、正确率、平均用时、截图 |
| 五、问题与改进 | 最大的困难和解决办法、还做不好的情况和改进计划 |
| 六、合规自查表 | 见 E.5 |
| 七、个人小结 | 每人 100～200 字 |

## E.5 合规自查表

| 序号 | 检查项 | 是 / 否 / 不涉及 | 说明 |
|---|---|---|---|
| 1 | 数据里有人脸、车牌等个人信息吗？如果有，是否获得本人同意或做了打码？ | | |
| 2 | 程序是否把人脸作为唯一的身份验证方式？有没有提供其他方式？ | | |
| 3 | 采集或保存的数据是否只用于本项目？是否会在项目结束后删除？ | | |
| 4 | 在公共场所拍摄时，是否有明显的提示？ | | |
| 5 | 程序是否生成或编辑了人像？是否加了“AI 生成”标识？ | | |
| 6 | 结果会不会对某一类人（肤色、性别、年龄、穿着）或某类场景（夜间、雨天）明显更差？测过吗？ | | |
| 7 | 界面上是否写明“仅供学习演示，结果可能有误”？ | | |
| 8 | （辅助驾驶类）是否说明本工具只做提醒、不能代替驾驶员，不得在真实驾驶中依赖它？ | | |
| 9 | 用到的模型、数据集、图片的许可是否允许这样使用？ | | |

依据：《中华人民共和国个人信息保护法》《人脸识别技术应用安全管理办法》《汽车数据安全管理若干规定（试行）》《人工智能生成合成内容标识办法》，详见 [9.7 节](../chapters/09-applications/index.md#97) 和 [8.6 节](../chapters/08-generative/index.md#86)。

## E.6 现场演示要求

每组 5 分钟演示 + 3 分钟提问：

1. 一句话说清项目做什么、给谁用（30 秒）；
2. 现场打开网页，用一个普通例子和一个“难”的例子演示（2 分钟）；
3. 讲清流程：用了哪些模型、哪些规则、参数怎么定的（1 分钟）；
4. 说一个程序出错的例子和原因（1 分钟）；
5. 说明合规方面做了哪些处理（30 秒）。

评分标准见[实验 9-3](../chapters/09-applications/index.md#9-3) 的“项目评分标准”。
